# 引用展示双级化设计(2026-08-12)

## 背景问题

回答已基于 RAG 生成,但部分引用被校验为 `verified=false` 后,前端展示「无直接引用来源」且不可点击。用户感知矛盾:"明明用了 RAG,怎么又说没有来源"。产品语义需要在「逐字引用」与「文档级引用」之间统一。

## 产品语义

| 级别 | 判定(后端) | 列表按钮 | 点开卡片 |
|------|-----------|---------|---------|
| 逐字引用 | 包含率 ≥ 0.6 且上下文 ≥ 8 字 | 正常样式,可点击 | 文档名 + 页码 + 原文片段 + "该结论有原文依据" |
| 文档级引用 | 低于上述标准(概括/改写/上下文过短) | 虚线弱化,可点击 | 仅文档名 + 页码,无片段、无警示 |

`verified` 字段语义从"真伪判别"变为"是否逐字匹配"。回答中 `[n]` 统一为"来源可查",仅证据强度不同。

## 改动范围

### 后端

- `build_citations` 逻辑不变(阈值 0.6、MIN_CONTEXT_CHARS=8 守卫),无需新增字段。
- 新增测试:降级引用仍返回 doc_name/page 供文档级展示。

### 前端

- `ChatArea.tsx`:!verified 按钮去掉 `cursor-not-allowed`,改虚线弱化但可点击;删除"(无直接引用来源)"文字。
- `CitationCard.tsx`:!verified 分支不渲染 snippet 与琥珀警示,仅保留标题 + 页码。

### 文档

- README「引用溯源」功能描述与数据流更新。
- DEV_LOG 新条目(dev-log skill,提出版本 v1.0.6,解决版本 v1.0.7)。

## 验证

- 后端:全套测试通过;真实链路 verified=True 与 False 两条路径分别手测。
- 前端:dev server 浏览器验证两种引用的展示与点击行为。
