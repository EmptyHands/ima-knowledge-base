# DEV-004 检索无结果兜底机制 设计文档

- 版本:v1.0
- 日期:2026-08-10
- 状态:已确认(经 brainstorming 逐节确认)
- 关联问题:DEV-004 检索无结果时无兜底机制,agent 直接回答没有索引

---

## 1. 问题定义

### 现状

- 知识库无文档(空库)提问时,仍调用大模型,提示词中无检索片段,大模型自由发挥,可能答出「没有索引」等无帮助内容
- 知识库有文档但检索无结果时,仅发一条状态「将基于已有知识作答」后照常调大模型,同样存在自由发挥问题
- 检索管线单一:纯向量(语义)检索,长尾查询(语义不匹配但字面命中)会漏召回,表现为「无结果」或低分答非所问

### 目标

1. 空库 / 检索无结果时给出**固定、可靠、可解释**的答复,不再依赖大模型自由发挥
2. 增加关键词(BM25)检索作为降级兜底,提升长尾查询召回
3. 告知用户无结果后,提供**联网搜索**的可选路径(agent 反问,用户确认后触发)

### 非目标

- ❌ 不做 dense + sparse 分数融合(如 RRF),本次为降级式,融合留作 README 未来扩展
- ❌ 不新增前端交互(无按钮、无弹窗),全靠 agent 文本反问
- ❌ 不迁移旧 collection 数据(存量索引提示用户删除重建)

---

## 2. 设计方案

### 2.1 存储层:双检索凭据(重索引)

每个文档片段在 Qdrant 中存两份检索凭据,存于同一个 point:

| 凭据 | 作用 | 生成方式 |
|------|------|---------|
| `dense`(原有) | 语义检索「意思相近」 | bge-m3 向量,不变 |
| `sparse`(新增) | 关键词检索「字面相同」 | jieba 分词 → 稳定哈希 term 映射 index,value = 词频(TF) |

- Collection 从单 dense 改为双向量(dense + sparse 命名向量)
- `_ensure_collection` 检测旧结构(缺 sparse)→ 沿用现有维度不匹配的迁移提示模式,提示删除重建
- 中文用 jieba 分词,英文按空白分词;稳定哈希避免分词顺序/字典变化导致 index 漂移
- `requirements.txt` 新增 `jieba`

### 2.2 检索层:三级降级管线

1. **第一级**:dense(语义)检索 top-k
   - 结果非空且最高分 ≥ 阈值(默认 0.35,新增配置项)→ 直接返回
   - 结果为空 **或** 最高分 < 阈值 → 进入第二级
2. **第二级**:sparse(BM25 关键词)检索 top-k,同样带 kb_id 过滤
   - 有结果 → 返回(结果附 `search_type: "sparse"` 标记)
   - 空 → 进入第三级
3. **第三级**:返回空结果 → 问答流程进入反问

阈值判断的意义:dense 检索在知识库有该库数据时总会返回 top-k,「完全为空」只发生在空库;长尾查询表现为低分,因此必须用「最高分低于阈值」作为主要触发条件。

### 2.3 交互层:空库判断与反问闭环

提问入口完整流程:

1. 数知识库文档数:
   - 0 个 → 固定回复「当前知识库还没有任何文档。是否需要联网搜索?回复『需要』即可。」**不调用大模型**,本轮结束
   - >0 → 走三级降级检索
2. 检索后仍有结果 → 原有问答链路,行为完全不变
3. 三级全空 → 固定回复「知识库中未找到与『<原问题>』相关的内容。是否需要联网搜索?回复『需要』即可。」**不调用大模型**,本轮结束
4. 用户确认联网:
   - 识别条件:会话最近一条助手消息是反问模板(按固定句式识别),且当前回复命中确认词(需要/要/好/是/可以/联网/搜索/用)
   - 触发:提取反问模板中的**原问题**,强制 `web=True` 重新检索作答(不依赖用户碰巧说出「网络/搜索」等意图关键词)

反问轮消息照常入库,SSE 事件序列与正常回答一致(status → done),前端无需改动。

### 2.4 配置变更

- `RETRIEVAL_DENSE_THRESHOLD`(默认 0.35):dense 结果最高分低于该值视为「未命中」,触发关键词兜底
- `.env.example` 同步补充说明;README 更新迁移步骤(删除旧 collection 重建)

## 4. 测试方案

**新增单元测试**

- 分词稳定性:同一句多次分词结果一致;中英文混合
- 稀疏向量生成:词频正确、index 哈希稳定、空文本安全
- 降级触发:dense 空 → sparse 兜底命中;dense 低分 → sparse 兜底命中;两轮皆空 → 返回空
- 确认词识别:确认词命中 / 普通回复不命中 / 非反问历史不触发

**新增流程测试(SSE)**

- 空库提问 → 回答为反问文本(空库版),事件序列 status → done,未调用大模型
- 有文档但检索全空 → 回答为反问文本(带原问题)
- 反问后回复「需要」→ 请求走强制联网检索

**回归**:现有 51 个测试保持全绿,原有问答链路不变。

## 5. 效果边界

| 场景 | 改前 | 改后 |
|------|------|------|
| 空知识库提问 | 调 LLM 自由发挥,可能答「没有索引」 | 固定反问「当前知识库还没有任何文档。是否需要联网搜索?回复『需要』即可」,不调 LLM |
| 语义检索全空 | 提示「将基于已有知识作答」后 LLM 自由发挥 | 关键词检索兜底;仍空 → 固定反问带原问题 |
| 语义检索分数太低 | 低分结果直接喂 LLM,答非所问 | 触发关键词兜底,命中则用关键词结果作答 |
| 用户回复「需要」 | 按普通问题处理,大概率不联网 | 提取原问题,强制联网搜索作答 |
| 正常检索有结果 | 正常 | 完全不变 |

**附带影响**

- 反问轮不调大模型,token 费用只降不增
- 新增 jieba 一个依赖
- 存量向量数据需一次性重建(删除旧 collection,重新导入文档)
- README「混合检索」未来扩展保留,本次不做分数融合
